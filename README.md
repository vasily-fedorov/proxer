# Proxer

Расширение Chrome (Manifest V3): проводит выбранные сайты через ваш прокси,
включается и выключается одним кликом или хоткеем.

Спецификация: `docs/superpowers/specs/2026-11-14-site-proxy-extension-design.md`
План реализации: `docs/superpowers/plans/2026-11-14-site-proxy-extension.md`

## Установка

1. Откройте `chrome://extensions/`.
2. Включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите корень этого репозитория.

Требуется Chrome 108 или новее (используется `webRequestAuthProvider` для
авторизации на прокси).

## Использование

1. Откройте страницу настроек расширения (правый клик по иконке → «Параметры»).
2. Укажите прокси: `1.2.3.4:8080`, `http://1.2.3.4:8080` или
   `socks5://1.2.3.4:1080`. Для HTTP-прокси можно заполнить логин и пароль;
   их также можно записать прямо в адрес: `http://user:pass@1.2.3.4:8080` —
   расширение разложит их по отдельным полям.
3. Откройте нужный сайт и нажмите на иконку Proxer (или `Ctrl+Shift+Y`,
   на macOS — `Command+Shift+Y`). Домен попадёт в список, вкладка
   перезагрузится, на иконке появится `ON`.
4. Повторный клик убирает покрывающее правило и возвращает сайт в прямое
   соединение.

Правило `example.com` покрывает сам домен и все его поддомены. Список и
настройки прокси сохраняются между запусками браузера.

## Проверка прокси

Настройки не сохраняются без успешной проверки доступа: кнопка «Сохранить
прокси» сначала делает настоящий запрос через указанный прокси. Проверяется
доступность, правильность схемы и логин/пароль. Если проверка не прошла,
конфигурация остаётся прежней, а в статусе показывается причина — теми же
словами, что и на странице сбоя.

Кнопка «Проверить» делает то же самое, но ничего не сохраняет — удобно, чтобы
убедиться в настройках заранее.

Что важно знать: на время проверки (обычно доли секунды, максимум 10 секунд)
браузер переключается на проверяемый прокси, поэтому трафик остальных вкладок
тоже идёт через него. Цель запроса — первый сайт из вашего списка, а если
список пуст — `example.com`.

## Как это работает

- Маршрутизация — PAC-скрипт с `mandatory: true`: если PAC не применился,
  Chrome не уходит в прямое соединение молча.
- Для доменов из списка PAC возвращает только прокси, без `; DIRECT`.
  Это осознанный fail-closed: сайт не откроется в обход прокси.
- Если прокси недоступен, вкладка показывает страницу расширения с причиной,
  адресом прокси (пароль замаскирован) и кнопкой «Повторить».
- Когда прокси не настроен или список пуст, расширение снимает свои настройки
  через `chrome.proxy.settings.clear`, возвращая системные/пользовательские.

## Ограничения

- Пароль прокси хранится в `chrome.storage.local` в открытом виде — Chrome не
  даёт другого способа, а `storage.sync` намеренно не используется, чтобы
  пароль не попадал в аккаунт Google.
- Авторизация SOCKS5 в Chrome невозможна: ни PAC, ни `onAuthRequired` не
  поддерживают креды для SOCKS. Поля логина/пароля для SOCKS5 отключены.
- HTTPS-прокси (TLS до самого прокси) не поддерживается — только `http://`
  и `socks5://`.
- После сбоя прокси в адресной строке будет `chrome-extension://…/proxy-error.html`,
  а не адрес сайта: Chrome не позволяет рисовать содержимое на своей странице
  ошибки.
- Прокси-настройки действуют на весь профиль, а не на отдельную вкладку.
- Если прокси-настройками управляет политика или другое расширение, изменить их
  не получится — страница настроек покажет предупреждение.
- SOCKS5 в Chrome всегда резолвит DNS на стороне прокси.

## Тесты

```bash
npm test        # юнит-тесты (node:test), без зависимостей
npm run test:e2e
```

`npm run test:e2e` поднимает локальный прокси и upstream-сервер, запускает
настоящий Chrome с загруженным расширением и проверяет через CDP:

- домен из списка реально идёт через прокси, домен вне списка — напрямую;
- на покрытом сайте горит badge `ON`, на непокрытом — нет;
- горячая клавиша зарегистрирована в манифесте;
- проверка прокси подтверждает рабочий прокси, блокирует сохранение на закрытом
  порту (конфигурация при этом не меняется) и проходит с прокси, требующим
  логин/пароль;
- прокси с Basic-авторизацией получает 407, расширение отдаёт логин/пароль,
  запрос проходит;
- при недоступном прокси вкладка оказывается на странице сбоя с адресом
  прокси и без пароля.

E2E требует браузер, который принимает `--load-extension`. Официальный
Google Chrome (брендированная сборка) этот ключ игнорирует, поэтому харнесс
сам ищет Chrome for Testing / Chromium в `~/.cache/ms-playwright`, а при
неудаче падает с понятной ошибкой. Явно задать бинарник:

```bash
CHROME_BIN=/path/to/chrome npm run test:e2e
```

Если в окружении нет рабочего sandbox (контейнер), харнесс уже передаёт
`--no-sandbox`. Для запуска с окном вместо headless:

```bash
HEADLESS=0 xvfb-run -a npm run test:e2e
```
